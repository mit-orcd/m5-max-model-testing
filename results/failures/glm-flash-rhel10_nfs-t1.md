*   **NFS with TLS support** (Excerpt 1): This feature adds Transport Layer Security (TLS) to Remote Procedure Call (RPC) traffic, enabling encrypted communication. It matters because it enhances security, though it currently relies on the kernel TLS feature which is a Technology Preview.
*   **IPv6 URL parsing in ReaR** (Excerpt 3): The tool now correctly interprets square brackets (e.g., `[2001:db8:ca2:6::101]`) in `nfs://` or `sshfs://` URLs. This matters because it allows users to successfully mount or backup to IPv6 addresses without needing workarounds or quoting.
*   **Common NFS mount options** (Excerpt 4): This documentation clarifies that `nolock` disables file locking (useful for old servers) and details how `rsize` and `wsize` affect performance by setting the maximum transfer size (default 1,048,576 bytes). It also explains security options (`sec=sys`, `krb5`, etc.) and their impact on authentication and performance overhead.
*   **Client-side caching via FS-Cache** (Excerpt 5): The documentation explains how FS-Cache improves performance by allowing the client to read data from a local cache (backed by ext3, ext4, or XFS) rather than the network. This significantly reduces server load and network bandwidth usage, though it may slightly slow down the client initially to build the cache.
