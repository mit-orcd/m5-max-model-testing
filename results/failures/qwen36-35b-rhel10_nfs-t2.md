*   **NFS with TLS support is fully supported**: NFS now supports Transport Layer Security (TLS) for RPC traffic, ensuring encrypted communication between clients and servers. This matters for security compliance, though it relies on kernel TLS (kTLS) which is currently a Technology Preview.
*   **RHEL 10.0 Release Notes did not list specific NFS performance or bug fixes**: The "Fixed issues" section for file systems and storage (Excerpt 2) contained no items relevant to NFS server or client performance or bugs; it only covered LVM/LUKS, multipathd, iSCSI, and fstrim.
*   **ReaR tool fixed NFS URL parsing for IPv6 addresses**: The ReaR backup tool was corrected to properly interpret square brackets in `nfs://` URLs for IPv6 addresses (e.g., `nfs://[::1]/...`). This matters because previously, using IPv6 addresses in NFS URLs caused ReaR to abort prematurely with an invalid scheme error, preventing automated backups or restores.
*   **NFS `rsize` and `wsize` maximum increased to 1,048,576 bytes**: The maximum bytes per single read or write operation is now 1,048,576 bytes (up from previous defaults). This matters because NFS uses the largest value supported by both client and server by default, allowing for larger data transfers per operation and potentially improving throughput compared to previous versions.
*   **NFS FS-Cache integration reduces network and server load**: Enabling FS-Cache allows NFS clients to cache content locally, satisfying read requests without consuming network bandwidth. This matters for performance by reducing server load and improving data retrieval speed, though it involves a trade-off where caching might slightly slow down the client itself.
