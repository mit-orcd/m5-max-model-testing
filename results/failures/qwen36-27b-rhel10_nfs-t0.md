*   **NFS with TLS support is fully supported:** NFS now supports Transport Layer Security (TLS) for RPC traffic, enabling encrypted communication between clients and servers. This matters because it significantly enhances security by preventing traffic sniffing and tampering, though it relies on the Technology Preview feature kTLS.
*   **ReaR NFS URL parsing fixed for IPv6:** The ReaR backup tool now correctly interprets square brackets in `nfs://` URLs (e.g., `nfs://[2001:db8::1]/share`). This matters because previous versions aborted prematurely when using IPv6 addresses in backup or output URLs, requiring manual workarounds with backslashes.
*   **Increased default maximum for `rsize` and `wsize`:** The client and server maximum for read and write buffer sizes is now 1,048,576 bytes (1 MB). This matters for performance as it allows for larger data transfers per operation, potentially reducing network overhead and improving throughput for large file operations.
*   **FS-Cache integration for NFS client-side caching:** RHEL 10 provides the `cachefiles` backend and `cachefilesd` service to enable transparent client-side caching of NFS content. This matters for performance as it can massively reduce network bandwidth usage and server load by satisfying read requests locally, though it may introduce slight latency on the client side.
