• **ReaR `nfs://` URL IPv6 parsing fix (Excerpt 3):** ReaR previously misinterpreted the square brackets around an IPv6 address in an `nfs://` (or `sshfs://`) URL as shell metacharacters, causing `BACKUP_URL`/`OUTPUT_URL` to abort with an "Invalid scheme" error. The parser was corrected so that `nfs://[2001:db8::…]/path` works natively. This matters because it removes a blocking bug for anyone backing up over NFS to an IPv6-only server and eliminates the need for the fragile backslash-quoting workaround.

• **`rsize` / `wsize` maximum of 1 048 576 bytes in RHEL 10 (Excerpt 4):** The documentation explicitly states that in RHEL 10 the client and server maximum for a single NFS read or write operation is 1 MB. This matters for throughput tuning: administrators can now size I/O to the full 1 MB ceiling (up from lower historical maxima on older releases), reducing the number of round-trips per transfer and improving large-file performance over TCP.

• **FS-Cache / `cachefilesd` client-side NFS caching (Excerpt 5):** RHEL 10 continues to provide the `cachefiles` back-end (via the `cachefilesd` daemon and the `cachefiles` kernel module) so that an NFS client can persistently cache file data on a local XFS, ext3, or ext4 volume under `/var/cache/fscache/`. This matters for performance because read requests are satisfied from local disk instead of the network, reducing both network bandwidth consumption and server load; the trade-off is a potential slight slowdown on the client side when cache misses or coherency checks occur.
