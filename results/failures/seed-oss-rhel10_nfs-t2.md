- **NFS with TLS support added**: RHEL 10 now fully supports NFS with Transport Layer Security (TLS), enabling encrypted RPC traffic between clients and servers. This enhances security by protecting data in transit, though it relies on kernel TLS (kTLS) which is a Technology Preview.  
- **Fixed IPv6 address handling in NFS URLs**: Previously, using IPv6 addresses in `nfs://` URLs required workarounds (e.g., quoting/backslashes) due to incorrect parsing of square brackets. Now, square brackets are properly interpreted, allowing direct use of IPv6 addresses like `nfs://[2001:db8::1]/path`.  
- **NFS client-side caching via FS-Cache**: NFS can leverage FS-Cache (using the `cachefilesd` service) to improve performance by caching data locally. This reduces server load and network bandwidth usage, with support for XFS/ext3/ext4 as cache backends (requires block mapping and extended attributes).  
- **NFS mount option defaults updated**: RHEL 10 NFS clients and servers use a maximum `rsize/wsize` of 1,048,576 bytes (1MB) by default (no fixed default before, now standardized for larger transfers).  
- **`vers` option compatibility**: The `vers` mount option (identical to `nfsvers`) is included for compatibility with older systems, simplifying migration or interaction with legacy NFS setups.
