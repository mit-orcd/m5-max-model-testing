- **NFS with TLS support added** – RHEL 10 now supports NFS over TLS (via kernel TLS) for encrypted RPC traffic. This enhances security but also introduces encryption overhead, affecting NFS client/server performance and providing a more secure alternative to clear‑text NFS.  
- **IPv6 address handling in nfs:// URLs fixed** – A bug caused ReaR to abort when an IPv6 address was used in an nfs:// or sshfs:// URL because brackets were incorrectly interpreted. The fix allows IPv6 addresses (e.g., `nfs://[2001:db8::101]/…`) without work‑arounds, restoring proper NFS client connectivity for IPv6‑based backups and improving reliability.  
- **Client‑side NFS caching via FS‑Cache (cachefilesd) introduced** – RHEL 10 adds native NFS client caching that leverages the `cachefiles` back‑end and the `cachefilesd` daemon to store frequently accessed data locally. This reduces network traffic and server load, speeds up read operations, and improves overall NFS performance while remaining transparent to users.
