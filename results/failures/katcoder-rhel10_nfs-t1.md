*   **NFS with TLS support is fully included**: NFS now supports Transport Layer Security (TLS) for RPC traffic, ensuring encrypted communication between clients and servers. This matters for security, though it relies on kernel TLS (kTLS), which remains a Technology Preview.
*   **ReaR fixed NFS URL IPv6 parsing**: The ReaR tool no longer interprets square brackets as shell metacharacters when parsing `nfs://` URLs containing IPv6 addresses. This matters because it allows automated recovery backups to NFS shares using IPv6 addresses without requiring manual workarounds.
*   **NFS `rsize` and `wsize` maximum increased to 1 MB**: The default maximum bytes for single NFS read or write operations is now 1,048,576 bytes (1 MB) for both client and server. This matters because it allows for larger I/O transfers by default, potentially improving throughput compared to previous limits.
*   **NFS client-side caching via FS-Cache supported**: The guide details enabling FS-Cache with the `cachefilesd` service to cache NFS content locally. This matters because it can reduce network bandwidth and server load by satisfying read requests locally, though it is a trade-off that may slightly slow the client.
