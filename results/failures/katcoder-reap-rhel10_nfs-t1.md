*   **NFS now supports TLS for RPC traffic (New Feature):** Enables encrypted communication between NFS clients and servers, enhancing security. This matters for protecting NFS data in transit, though it relies on the Technology Preview kTLS feature.
*   **NFS mount URLs now correctly parse IPv6 addresses in square brackets (Bug Fix):** ReaR previously aborted when using `nfs://` URLs with IPv6 addresses because brackets were interpreted as shell metacharacters. This fix allows standard IPv6 syntax (e.g., `nfs://[2001:db8::1]/share`) to work without manual backslash escaping.
*   **FS-Cache support added for NFS client-side caching (New Feature):** Introduces FS-Cache integration via the `cachefilesd` service to improve NFS client performance by satisfying read requests locally, reducing network bandwidth and server load. This matters for workloads with repeated or large file access patterns, provided the cache backend (ext3, ext4, or xfs) is properly configured.
*   **NFS `rsize` and `wsize` max defaults increased to 1,048,576 bytes (Configuration Change):** The maximum supported read/write size for NFS mounts is now 1 MB. This matters for performance as it allows larger I/O operations by default, reducing overhead compared to smaller transfer sizes.
