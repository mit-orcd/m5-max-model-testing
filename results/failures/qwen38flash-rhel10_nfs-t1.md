*   **Added full support for NFS over TLS (RHEL 10.0 New Feature):** NFS now supports Transport Layer Security (TLS) to encrypt RPC traffic between clients and servers. This enhances security by ensuring encrypted communication, relying on kernel TLS (kTLS), which is currently a Technology Preview feature.
*   **Fixed IPv6 address parsing for NFS URLs in ReaR (RHEL 10.0 Bug Fix):** Resolved an issue where ReaR aborted with an error when `BACKUP_URL` or `OUTPUT_URL` used the `nfs://` scheme with IPv6 addresses enclosed in square brackets (e.g., `nfs://[::1]/path`). ReaR now correctly interprets the brackets, allowing IPv6 addresses to be used in NFS backup configurations without requiring manual escaping workarounds.
*   **Documented `rsize` and `wsize` performance defaults (Managing File Systems):** The documentation clarifies that `rsize` and `wsize` options control the maximum bytes transferred in single NFS read/write operations. In RHEL 10, the default behavior uses the largest value supported by both client and server, with a maximum of 1,048,576 bytes. Understanding these defaults is critical for tuning NFS throughput.
*   **Detailed NFS client caching capabilities via FS-Cache (Managing File Systems):** Introduced guidelines for using FS-Cache to improve NFS client performance and reduce server load by caching data locally. The documentation explains that while FS-Cache can reduce network bandwidth consumption by satisfying read requests locally, it may introduce client-side latency, representing a trade-off between network efficiency and client I/O speed.
