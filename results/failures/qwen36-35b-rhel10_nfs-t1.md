*   **NFS with TLS support added**: RHEL 10 now fully supports Network File System (NFS) with Transport Layer Security (TLS), enabling encrypted communication between clients and servers via RPC traffic. This matters because it significantly enhances security by preventing traffic sniffing, though it currently relies on kernel TLS (kTLS), which is available as a Technology Preview.
*   **IPv6 address parsing fix for NFS URLs**: The ReaR tool was updated to correctly interpret square brackets around IPv6 addresses in `nfs://` URLs (e.g., `nfs://[2001:db8::1]/...`). This matters because it prevents premature abortion of backup or output operations that previously failed due to incorrect shell metacharacter interpretation, allowing users to use IPv6 addresses without workarounds.
*   **Increased default `rsize` and `wsize` limits**: The maximum number of bytes transferred in a single NFS read or write operation is now 1,048,576 bytes (up from previous defaults). This matters because it allows NFS to utilize the largest possible value supported by both client and server, potentially improving throughput and performance for large data transfers.
*   **FS-Cache integration for NFS**: NFS now leverages FS-Cache to enable client-side caching of content. This matters because it improves performance by reducing server load and network bandwidth consumption through efficient local data retrieval, while handling partial caching and hiding cache-related I/O errors transparently.
*   **FS-Cache backend requirements defined**: FS-Cache requires a cache back end (`cachefiles`) mounted on a block-based file system supporting `bmap` and extended attributes (specifically XFS, ext3, or ext4). This matters because administrators must ensure the cache directory uses a compatible file system with extended attributes to enable caching services effectively.
*   **FS-Cache performance trade-off noted**: Using FS-Cache to cache NFS traffic is described as a compromise that may slow down the client locally but massively reduces network and server loading. This matters because it highlights the performance impact of enabling caching, allowing administrators to balance local responsiveness against network efficiency.
