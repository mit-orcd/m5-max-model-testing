*   **NFS with TLS Support**: RHEL 10 fully supports Transport Layer Security (TLS) for NFS RPC traffic. This matters because it enables encrypted communication between clients and servers, enhancing security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **Increased Maximum I/O Size**: The default maximum values for `rsize` and `wsize` mount options have increased to 1,048,576 bytes (1 MiB). This matters because it allows the client and server to negotiate larger data transfer blocks by default, potentially improving throughput and reducing protocol overhead.
*   **FS-Cache Integration for Performance**: NFS now supports client-side caching via FS-Cache and the `cachefilesd` daemon. This matters because it reduces server load and network bandwidth consumption by satisfying read requests locally from a persistent cache (backed by XFS, ext3, or ext4), though it may introduce local I/O latency.
*   **ReaR IPv6 URL Parsing Fix**: A bug in ReaR (Relax-and-Recover) has been fixed regarding the parsing of `nfs://` URLs containing IPv6 addresses in square brackets. This matters because users can now correctly specify IPv6 addresses in backup/restore output URLs without using manual shell escaping workarounds.
