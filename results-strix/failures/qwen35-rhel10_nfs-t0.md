*   **NFS with TLS support added**: RHEL 10 now fully supports Network File System (NFS) with Transport Layer Security (TLS) for Remote Procedure Call (RPC) traffic, ensuring encrypted communication between clients and servers. This matters for enhancing NFS security, though it relies on kernel TLS (kTLS) which is currently a Technology Preview.
*   **ReaR NFS URL IPv6 parsing fixed**: The ReaR tool was updated to correctly interpret square brackets in IPv6 addresses within `nfs://` URLs (e.g., `nfs://[::1]/...`), preventing premature aborts during backup or restore operations. This matters because it enables the use of IPv6 addresses in NFS URLs without requiring manual escaping workarounds.
*   **NFS `rsize` and `wsize` defaults clarified**: The maximum default value for NFS read (`rsize`) and write (`wsize`) operations in RHEL 10 is set to 1,048,576 bytes (1 MB), representing the largest value supported by both client and server. This matters for optimizing data transfer efficiency and ensuring consistent performance expectations across the stack.
*   **NFS FS-Cache performance optimization**: NFS caching via FS-Cache is supported to improve network file system performance, reduce server load, and enable efficient local data retrieval. This matters because it allows clients to satisfy read requests locally without consuming network bandwidth, though it involves a trade-off where caching may slightly slow the client while significantly reducing network and server load.
*   **NFS mount option compatibility**: The `vers` option is confirmed as identical to `nfsvers` for compatibility reasons. This matters for ensuring consistent configuration syntax across different RHEL versions and documentation.
