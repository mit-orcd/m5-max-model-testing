- **NFS with TLS support**: NFS now fully supports Transport Layer Security (TLS) for RPC traffic, encrypting communication between clients and servers. This enhances security by mitigating risks of unauthorized access to unencrypted NFS traffic, though it relies on kernel TLS (kTLS) which is in Technology Preview.  
- **NFS IPv6 URL parsing fix**: ReaR and related tools now correctly interpret IPv6 addresses in `nfs://` URLs when enclosed in square brackets (e.g., `nfs://[2001:db8::1]/path`). Previously, square brackets were misread as shell metacharacters, causing errors; this fix enables NFS clients to use IPv6 addresses without workarounds, improving IPv6 network compatibility.  
- **NFS `rsize`/`wsize` maximum size increase**: Red Hat Enterprise Linux 10 sets the client and server maximum for `rsize` (read block size) and `wsize` (write block size) to 1,048,576 bytes (1MB). Larger block sizes reduce the number of RPC calls needed for data transfer, potentially improving NFS read/write performance.  
- **NFS client-side caching via FS-Cache**: NFS clients can now use FS-Cache (via the `cachefilesd` service) to cache content locally on supported block-based file systems (XFS/ext3/ext4). This reduces network traffic (by satisfying read requests from cache) and server load, while enabling faster local data retrieval for repeated access patterns.
