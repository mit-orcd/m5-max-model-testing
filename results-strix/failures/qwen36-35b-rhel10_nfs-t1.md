*   **NFS with TLS support is fully enabled**: NFS now supports Transport Layer Security (TLS) for RPC traffic, providing encrypted communication between clients and servers. This matters for security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR correctly parses IPv6 addresses in NFS URLs**: ReaR no longer treats square brackets in `nfs://` URLs as shell metacharacters, allowing users to specify IPv6 addresses for NFS backup/output destinations. This fixes premature aborts and allows native IPv6 usage without complex quoting workarounds.
*   **Default `rsize` and `wsize` maximums increased**: The maximum bytes for single NFS read/write operations is now 1,048,576 bytes (1 MB) for both client and server. This matters for performance as it allows larger data transfers per operation compared to previous defaults, potentially improving throughput.
*   **NFS client-side caching via FS-Cache is documented**: RHEL 10 supports FS-Cache to cache NFS content locally. This matters for performance by reducing network load and server strain, enabling efficient local data retrieval, though it requires specific back-end file systems (XFS, ext3, ext4) and a compromise between local caching speed and potential client slowdowns.
