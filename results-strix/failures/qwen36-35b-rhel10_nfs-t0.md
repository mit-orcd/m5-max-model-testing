*   **NFS with TLS support is fully supported**: Enables Transport Layer Security (TLS) for RPC traffic to ensure encrypted communication between clients and servers. This matters for enhancing NFS security, though it relies on kernel TLS (kTLS) which is currently a Technology Preview.
*   **ReaR correctly parses IPv6 addresses in NFS URLs**: Fixes a bug where square brackets in IPv6 addresses (e.g., `nfs://[::1]/...`) were interpreted as shell metacharacters, causing ReaR to abort. This matters because it allows users to correctly use IPv6 addresses in NFS backup and output URLs without manual workarounds.
*   **Default `rsize` and `wsize` increased to 1,048,576 bytes**: The maximum number of bytes for single NFS read/write operations is now 1 MB (up from previous defaults). This matters because it allows for larger data transfers per operation, potentially improving throughput and performance for NFS mounts.
*   **NFS client-side caching via FS-Cache is documented and supported**: Introduces support for leveraging FS-Cache to cache NFS content locally. This matters because it can improve performance by reducing network latency and server load, allowing efficient local data retrieval for read requests.
*   **FS-Cache requires specific back-end file systems**: FS-Cache requires the cache back-end (mounted at `/var/cache/fscache/`) to be XFS, ext3, or ext4 with extended attributes. This matters for performance configuration, as using unsupported file systems will prevent the caching mechanism from functioning.
