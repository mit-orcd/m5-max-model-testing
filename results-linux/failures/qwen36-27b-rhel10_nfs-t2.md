*   **NFS with TLS Support**: RHEL 10 fully supports Transport Layer Security (TLS) for NFS, encrypting RPC traffic between clients and servers via kernel TLS (kTLS). This enhances security by ensuring encrypted communication, though the underlying kTLS feature is currently a Technology Preview.
*   **ReaR NFS/SSHFS IPv6 URL Parsing Fix**: The ReaR backup tool was fixed to correctly interpret square brackets in `nfs://` (and `sshfs://`) URLs containing IPv6 addresses. Previously, this caused premature aborts due to shell metacharacter interpretation errors; users can now use standard IPv6 bracket notation (e.g., `nfs://[::1]/...`) without workarounds.
*   **Increased Default rsize/wsize Limits**: The maximum supported value for NFS read (`rsize`) and write (`wsize`) operations on both client and server is now 1,048,576 bytes (1 MB). By default, NFS negotiates the largest possible value supported by both ends, potentially improving throughput for large file transfers compared to previous lower defaults.
*   **FS-Cache for NFS Client-Side Caching**: The documentation details the use of FS-Cache (via `cachefiles`) to improve NFS client performance by caching data locally. This reduces server load and network bandwidth consumption by satisfying read requests from the local cache, though it introduces a trade-off where write latency or cache coherency management may slightly impact client speed.
