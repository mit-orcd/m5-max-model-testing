*   **NFS with TLS support is fully enabled**: NFS now supports Transport Layer Security (TLS) for RPC traffic, ensuring encrypted communication between clients and servers. This matters for security compliance and data protection, though it relies on the Technology Preview status of kernel TLS (kTLS).
*   **ReaR now correctly parses IPv6 addresses in NFS URLs**: The `nfs://` URL scheme in ReaR no longer misinterprets square brackets around IPv6 addresses as shell metacharacters. This matters because it allows automated backup/restore workflows to correctly target NFS servers using IPv6 addresses without requiring workarounds.
*   **Default `rsize` and `wsize` values increased to 1,048,576 bytes**: The maximum bytes for single NFS read/write operations are now set to 1 MB by default (up from previous limits). This matters because larger transfer sizes can significantly improve I/O throughput and overall NFS performance.
*   **NFS client-side caching via FS-Cache is documented and supported**: The system now supports leveraging FS-Cache with the `cachefilesd` service to cache NFS content locally. This matters because it reduces network bandwidth usage and server load by satisfying read requests locally, though it requires a compatible back-end file system (XFS, ext3, or ext4).
*   **FS-Cache hides local cache I/O errors from the client**: FS-Cache is designed to hide input/output errors occurring in the cache from the client file system driver. This matters because it improves client-side stability and transparency, allowing the system to handle cache backend issues without disrupting the mounted NFS file system operation.
