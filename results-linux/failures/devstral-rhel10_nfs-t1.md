- **NFS with TLS support**: NFS now supports TLS for encrypted RPC traffic, enhancing security. This matters because it provides confidential communication between NFS clients and servers, preventing eavesdropping and tampering.
- **IPv6 address support in NFS URLs**: IPv6 addresses enclosed in square brackets (e.g., `[::1]`) are now properly parsed in `nfs://` URLs, fixing issues where ReaR would abort due to incorrect interpretation of brackets. This matters because it allows users to use IPv6 addresses directly in NFS mount paths without workarounds.
- **NFS mount options**: Default values for `rsize` and `wsize` are now up to 1,048,576 bytes (1 MiB), improving read/write performance for NFS. This matters because larger transfer sizes reduce the number of round trips needed for I/O operations, improving throughput.
- **NFS client-side caching (FS-Cache)**: FS-Cache is enabled for NFS to improve performance by caching data locally, reducing server load and network traffic. This matters because it accelerates repeated read operations and reduces latency for frequently accessed files.
- **`cachefilesd` service**: The `cachefilesd` daemon manages FS-Cache, allowing persistent NFS caching on supported filesystems (XFS, ext3, ext4). This matters because it provides a configurable and reliable caching backend for NFS, improving overall system performance.
