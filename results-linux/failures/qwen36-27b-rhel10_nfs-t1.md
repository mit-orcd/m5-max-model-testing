*   **NFS with TLS support added:** RHEL 10 fully supports NFS with Transport Layer Security (TLS) for RPC traffic, enabling encrypted communication between clients and servers. This matters for enhancing security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR NFS URL parsing fixed for IPv6:** A bug in the ReaR backup tool that prevented the use of IPv6 addresses (enclosed in square brackets) in `nfs://` URLs has been fixed. This matters because it allows administrators to correctly configure NFS backup outputs using IPv6 without requiring complex workarounds or encountering premature aborts.
*   **Clarified NFS mount option defaults and limits:** The documentation clarifies that the default `rsize` and `wsize` are dynamically negotiated to the largest value supported by both client and server, with a maximum of 1,048,576 bytes in RHEL 10. This matters for performance tuning, as users can now confirm the upper limits for read/write operations.
*   **FS-Cache for NFS performance optimization:** The guide details the use of FS-Cache with the `cachefiles` backend to improve NFS client performance. This matters because it reduces network and server load by satisfying read requests locally, though administrators should be aware that it may introduce slight client-side latency in exchange for reduced bandwidth usage.
