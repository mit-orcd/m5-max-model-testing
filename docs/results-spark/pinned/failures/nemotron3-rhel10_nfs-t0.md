- **NFS with TLS support**: RHEL 10 fully supports NFS with Transport Layer Security (TLS) for encrypting RPC traffic between clients and servers, enhancing security for NFS communications. This matters because it protects data in transit from eavesdropping and tampering, though it relies on kernel TLS (kTLS), which remains a Technology Preview for general use.

- **IPv6 address handling in NFS URLs**: Fixed an issue where IPv6 addresses enclosed in square brackets (e.g., `[2001:db8:ca2:6::101]`) in `nfs://` or `sshfs://` URLs were incorrectly interpreted as shell metacharacters, causing ReaR to fail. Now, such URLs are parsed correctly, enabling reliable use of IPv6 in NFS-based backup and output configurations without workarounds.

- **Client-side caching via FS-Cache**: NFS clients can now leverage FS-Cache with the `cachefiles` backend to cache NFS content locally, improving read performance, reducing server and network load, and enabling efficient local data retrieval. This matters because it significantly boosts NFS performance for repetitive read workloads while maintaining transparency and handling partial caching and I/O errors gracefully. Supported cache back ends include XFS, ext3, and ext4 with extended attributes.
