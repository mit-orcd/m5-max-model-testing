*   **NFS with TLS support added:** NFS traffic can now be encrypted using Transport Layer Security (TLS) via kernel TLS (kTLS). This matters because it enhances security by ensuring encrypted communication between clients and servers without requiring application-level changes.
*   **IPv6 address support in NFS URLs fixed:** The ReaR tool now correctly interprets IPv6 addresses (enclosed in square brackets) in `nfs://` URLs. This matters because it resolves a bug that caused ReaR to abort when using IPv6 addresses in backup or output URLs.
*   **NFS rsize and wsize maximums increased:** The maximum transfer size for NFS read and write operations is now 1,048,576 bytes (1 MiB). This matters because it allows larger data chunks to be transferred in a single operation, potentially improving throughput and reducing the number of round trips.
*   **NFS client-side caching (FS-Cache) available:** The `cachefilesd` service can be used to cache NFS content on the client side. This matters because it reduces network and server load by satisfying read requests locally and enables efficient local data retrieval.
*   **NFS mount options documentation updated:** The `vers` option is now documented as an alias for `nfsvers` for compatibility. This matters because it clarifies that both options function identically for NFS version selection.
