- **NFS with TLS support (new in RHEL 10):** NFS RPC traffic can now be encrypted via TLS (backed by kernel TLS / kTLS, itself a Technology Preview). *Why it matters:* Adds encryption overhead to every RPC exchange, which can reduce throughput compared to unencrypted `sec=sys` or `sec=krb5i` mounts, but eliminates the need for IPsec or `sec=krb5p` for transport-layer protection.

- **`rsize` / `wsize` ceiling in RHEL 10 is 1 048 576 bytes (1 MiB):** The documentation now states that both client and server cap per-operation read/write size at 1 MiB. *Why it matters:* This is the hard maximum for a single NFS I/O; workloads that issue small reads/writes (e.g., many 4 KiB transfers) will see higher per-operation RPC overhead than workloads that saturate the 1 MiB limit, so tuning application I/O size to the 1 MiB ceiling is the primary lever for NFS throughput.

- **`sec=krb5p` explicitly flagged as highest-overhead security mode:** The mount-option reference notes that Kerberos 5 with encryption "involves the most performance overhead" among the `sec=` options. *Why it matters:* Administrators choosing between `krb5`, `krb5i`, and `krb5p` should expect measurable latency and throughput penalties with `krb5p` (per-packet encryption) versus `krb5i` (integrity only) or `krb5` (authentication only), and budget accordingly for NFS workloads.

- **ReaR no longer aborts on `nfs://` URLs containing IPv6 addresses (bug fix):** Previously ReaR misparsed the square brackets in an IPv6 literal (e.g., `nfs://[2001:db8:…]/root/REAR`) as shell metacharacters, causing an "Invalid scheme" error and premature exit. The fix stops bracket interpretation when parsing `sshfs://` and `nfs://` schemes. *Why it matters:* NFS backup/restore over IPv6-only networks (or mixed v4/v6 environments) now works without the old backslash-escaping workaround, removing a failure mode in disaster-recovery automation that relied on NFS.
