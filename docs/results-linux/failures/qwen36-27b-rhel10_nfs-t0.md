*   **NFS with TLS support is fully supported**: NFS now supports Transport Layer Security (TLS) for RPC traffic, enabling encrypted communication between clients and servers. This matters because it enhances security by protecting data in transit, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR NFS URL parsing fixed for IPv6**: The ReaR backup tool now correctly interprets square brackets in `nfs://` URLs containing IPv6 addresses. This matters because it allows users to specify IPv6 NFS servers in `BACKUP_URL` or `OUTPUT_URL` without requiring complex workarounds or encountering premature abort errors.
*   **Increased default maximum for `rsize` and `wsize`**: In RHEL 10, the maximum supported value for NFS read (`rsize`) and write (`wsize`) operations is 1,048,576 bytes. This matters because larger transfer sizes can improve NFS throughput and performance by reducing the number of round-trips required for large file operations.
*   **FS-Cache integration for NFS client-side caching**: NFS clients can leverage FS-Cache (via the `cachefiles` backend) to cache content locally. This matters because it can significantly reduce network bandwidth usage and server load by satisfying read requests from the local cache, although it may introduce slight latency overhead on the client side.
