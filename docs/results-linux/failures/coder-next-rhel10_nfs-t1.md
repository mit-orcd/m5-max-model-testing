- **NFS with TLS support added in RHEL 10**: NFS now supports TLS for RPC traffic, enhancing security via encrypted communication between clients and servers. *Matters because it enables secure NFS deployments, though dependent on kTLS (Technology Preview), which may affect production readiness.*  
- **Default rsize/wsize increased to 1,048,576 bytes in RHEL 10 NFS**: NFS client and server now support up to 1 MiB for read/write operations by default, instead of smaller legacy values. *Matters because larger I/O sizes reduce CPU overhead and improve throughput, especially on high-bandwidth networks.*  
- **`sec=krb5p` still supported but performance overhead noted**: Kerberos encryption (`sec=krb5p`) remains available for NFS, but documentation explicitly flags it as having the highest performance cost. *Matters because it informs administrators of trade-offs when choosing strong security.*  
- **IPv6 support in nfs:// URLs fixed in ReaR (Relax-and-Recover)**: Square brackets around IPv6 addresses in `nfs://` URLs (e.g., `nfs://[2001:db8::1]/path`) are now correctly parsed, resolving premature aborts. *Matters because it enables reliable use of IPv6 addresses in backup/restore workflows involving NFS.*  
- **No direct NFS bug fixes in multipath, LUKS, or storage stack**: Other fixed issues (e.g., multipathd, LUKS, iSCSI) are unrelated to NFS and omitted per instructions.  
- **FS-Cache integration for NFS remains unchanged but documented**: FS-Cache (via `cachefiles`) continues to support NFS performance optimization by caching data locally. *Matters because it enables offline read access, reduces network/server load, and improves latency for repeated reads—though requires manual setup (XFS/ext3/ext4 cache backend, `cachefilesd`).*
