*   **NFS now supports TLS encryption:** NFS traffic can now be encrypted using Transport Layer Security (TLS) via the kernel TLS (kTLS) feature. This matters because it ensures secure, encrypted communication between clients and servers, enhancing data security.
*   **IPv6 addresses are now supported in NFS URLs:** The parsing of `nfs://` and `sshfs://` URLs has been fixed to correctly handle IPv6 addresses enclosed in square brackets (e.g., `nfs://[2001:db8:ca2:6::101]/root/REAR`). This matters because it allows users to utilize IPv6 addresses for backup and output URLs without encountering syntax errors.
*   **Increased default NFS read/write size:** The maximum size for NFS read (`rsize`) and write (`wsize`) operations has been raised to 1,048,576 bytes (1 MiB) for both client and server compatibility. This matters because it significantly increases the amount of data transferred per network request, thereby improving overall file transfer performance.
*   **FS-Cache support for NFS:** The FS-Cache subsystem now provides a persistent local cache for NFS content. This matters because it reduces network and server load by serving read requests locally, while maintaining transparency to the user and allowing for partial file caching.
*   **NFS timeout tuning:** The `timeo` mount option (defaulting to 600 tenths of a second, or 60 seconds, for TCP) is available to control the wait time before retrying an NFS request with linear backoff. This matters because it allows administrators to optimize the client's resilience to network latency or server unresponsiveness.
*   **NFS retry tuning:** The `retrans` mount option controls the number of retries for NFS requests before recovery actions are taken. This matters because it allows administrators to balance between quick failure detection and retrying transient network errors.
*   **Explicit NFS version syntax:** The `vers` mount option is now explicitly supported for compatibility reasons. This matters because it provides an alternative way to specify the NFS protocol version, making configuration more straightforward for users who prefer this syntax over `nfsvers`.
*   **Reduced memory usage for NVMe multipathing:** A memory leak in `multipathd` monitoring code when using `enable_foreign` for native NVMe multipathing has been fixed. This matters because it allows the system to monitor multipathed NVMe devices without consuming increasing amounts of memory.
*   **Fixed `multipathd` crash on NetApp prioritizers:** The error logging code for the ontap prioritizer has been fixed to prevent buffer overflow. This matters because it prevents the `multipathd` service from crashing when configured with unsupported NetApp paths.
