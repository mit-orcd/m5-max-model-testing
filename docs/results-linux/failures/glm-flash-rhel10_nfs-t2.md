*   **NFSv4 default port changed:** The default TCP port for NFSv4 mounts is now **2049** (standard NFS port), whereas previously the `rpcbind` service was queried. This change simplifies configuration and eliminates unnecessary RPC checks.
*   **Increased NFS I/O buffer sizes:** The default and maximum size for NFS read (`rsize`) and write (`wsize`) operations is now **1,048,576 bytes (1 MiB)**. This increases throughput for large file transfers.
*   **IPv6 support for NFS URLs:** The `rear` tool now correctly interprets IPv6 addresses (e.g., `[2001:db8:ca2:6::101]`) in `nfs://` URLs. Previously, square brackets were treated as shell metacharacters, causing errors when using IPv6 addresses in backup configurations.
*   **TLS support for NFS (Technology Preview):** NFS can now be configured with Transport Layer Security (TLS). This encrypts RPC traffic between clients and servers for enhanced security, though it relies on Kernel TLS (kTLS), which is currently a Technology Preview feature.
*   **Increased maximum `rsize` and `wsize` values:** The maximum supported transfer size for NFS read and write operations has been increased to **1,048,576 bytes** (previously lower). This improves performance for high-bandwidth networks.
*   **Client-side caching with FS-Cache:** NFS performance can be improved by enabling the `cachefilesd` service with the `fscache` mount option. This allows the client to cache file content locally, reducing server load and network bandwidth consumption for read-heavy workloads.
*   **NFS URL bracket handling:** The `rear` tool is fixed to not interpret square brackets as shell metacharacters when parsing `nfs://` URLs. This allows users to use IPv6 addresses (e.g., `[::1]`) in `BACKUP_URL` or `OUTPUT_URL` without workarounds like backslashes.
