- **NFS with TLS support added**: RHEL 10 now fully supports Transport Layer Security (TLS) for NFS, enabling encrypted RPC traffic between clients and servers. This matters by significantly enhancing security against traffic sniffing and tampering, though it relies on the kernel TLS (kTLS) feature which is currently a Technology Preview.
- **IPv6 address handling in NFS URLs fixed**: The ReaR backup tool now correctly interprets IPv6 addresses enclosed in square brackets (e.g., `nfs://[::1]/path`) within `BACKUP_URL` or `OUTPUT_URL` parameters. This matters because it resolves a bug where the tool previously aborted with an "Invalid scheme" error, allowing automated backups to NFS shares using IPv6 without requiring manual workarounds.
- **NFS client-side caching (FS-Cache) capabilities**: The documentation details the use of FS-Cache with NFS to improve performance by caching data locally on the client. This matters because it reduces network bandwidth consumption and server load by satisfying read requests from the local cache, though it may introduce a slight performance overhead on the client side depending on the workload.
- **Default maximum read/write sizes defined**: In RHEL 10, the default maximum values for `rsize` and `wsize` (data transfer sizes) are set to 1,048,576 bytes (1 MiB) for both client and server. This matters for performance tuning as it ensures the system automatically negotiates the largest possible data transfer size supported by both ends, optimizing throughput for large file operations.
- **NFS mount option `port` behavior clarified for NFSv4**: For NFSv4, if the `port` option is not specified, the client now uses the standard TCP port 2049 and skips querying the `rpcbind` service. This matters for connection reliability and speed, as it reduces dependency on the `rpcbind` service for NFSv4 mounts, which typically use a fixed port.
