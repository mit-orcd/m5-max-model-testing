*   **NFS with TLS support is fully supported**: NFS now supports Transport Layer Security (TLS) for RPC traffic, enabling encrypted communication between clients and servers. This matters because it enhances security by protecting data in transit, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR NFS URL parsing fixed for IPv6**: The ReaR backup tool now correctly interprets square brackets in `nfs://` URLs containing IPv6 addresses. This matters because it allows users to specify IPv6 NFS servers in `BACKUP_URL` or `OUTPUT_URL` without requiring complex shell escaping workarounds that previously caused premature aborts.
*   **Increased default maximum for rsize and wsize**: In RHEL 10, the maximum supported value for NFS read (`rsize`) and write (`wsize`) operations is 1,048,576 bytes. This matters because larger transfer sizes can improve throughput and performance for both NFS clients and servers compared to previous defaults.
*   **FS-Cache integration for NFS client performance**: NFS clients can leverage FS-Cache (via the `cachefiles` backend) to cache content locally. This matters because it can significantly reduce network bandwidth usage and server load by satisfying read requests from local storage, although it may introduce slight latency overhead on the client side.
