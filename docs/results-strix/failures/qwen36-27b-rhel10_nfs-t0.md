*   **NFS with TLS support**: RHEL 10 fully supports NFS with Transport Layer Security (TLS) to encrypt RPC traffic between clients and servers. This matters for security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR NFS URL parsing fix**: The ReaR backup tool now correctly interprets square brackets in `nfs://` URLs containing IPv6 addresses (e.g., `nfs://[2001:db8::1]/share`). Previously, these brackets were misinterpreted as shell metacharacters, causing premature aborts; this fix allows seamless IPv6 NFS backup configurations.
*   **Increased default rsize/wsize limits**: The maximum supported value for NFS read (`rsize`) and write (`wsize`) operations is now 1,048,576 bytes (1 MB) on both client and server. This allows for larger single-operation transfers, potentially improving throughput for large file operations compared to previous defaults.
*   **FS-Cache for NFS performance**: Documentation highlights the use of FS-Cache (via `cachefiles`) to cache NFS content locally. This improves client-side read performance and reduces network/server load by satisfying requests from local storage, though it may introduce slight latency for cache misses.
