*   **NFS over TLS support added**: RHEL 10 now fully supports Network File System with Transport Layer Security (TLS) for RPC traffic. This matters for security by ensuring encrypted communication between clients and servers, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **IPv6 address handling in backup URLs fixed**: A bug preventing the use of IPv6 addresses (enclosed in square brackets) in `nfs://` URLs for ReaR backups has been resolved. This matters for system administrators using NFS for automated backups in IPv6 environments, as the previous bug caused premature aborts.
*   **NFS client read/write size defaults updated**: The maximum supported value for `rsize` and `wsize` (read/write buffer sizes) is now 1,048,576 bytes (1 MiB) for both client and server. This matters for performance tuning, as larger buffer sizes can significantly improve throughput for large file transfers.
*   **Client-side caching (FS-Cache) capabilities described**: Documentation details the use of FS-Cache to improve NFS performance by reducing server load and network bandwidth through local data caching. This matters for optimizing read-heavy workloads, though administrators must note it can introduce client-side latency and requires a compatible local cache backend (XFS, ext3, or ext4).
