*   **NFS with TLS support**: RHEL 10 fully supports NFS with Transport Layer Security (TLS) to encrypt RPC traffic between clients and servers. This matters for security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR NFS URL parsing fix**: The ReaR backup tool now correctly interprets square brackets in IPv6 addresses within `nfs://` URLs (e.g., `nfs://[::1]/...`). Previously, these brackets were treated as shell metacharacters, causing premature aborts; this fix ensures reliable backup configurations using IPv6 NFS targets.
*   **Increased default rsize/wsize limits**: The maximum supported value for NFS read (`rsize`) and write (`wsize`) operations is now 1,048,576 bytes (1 MB) for both client and server. This allows for larger data transfers per operation, potentially improving throughput for compatible workloads.
*   **FS-Cache for NFS performance**: RHEL 10 documentation highlights the use of FS-Cache (via the `cachefiles` backend) to cache NFS content locally. This improves performance by satisfying read requests from local storage, reducing network bandwidth usage and server load, though it may introduce slight latency overhead on the client side.
