- **NFS with TLS support added**: RHEL 10 now fully supports Transport Layer Security (TLS) for NFS RPC traffic, enabling encrypted communication between clients and servers; this matters for enhancing security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
- **IPv6 address handling in NFS URLs fixed**: ReaR (Relax-and-Recover) now correctly interprets IPv6 addresses enclosed in square brackets (e.g., `nfs://[::1]/path`) in `BACKUP_URL` or `OUTPUT_URL` without requiring manual escaping; this matters because it prevents premature aborts during backup/restore operations when using IPv6 NFS targets.
- **NFS client-side caching via FS-Cache documented**: RHEL 10 supports using FS-Cache with NFS to improve performance by caching data locally, reducing server load and network bandwidth usage; this matters for optimizing read-heavy workloads, though it may introduce slight client-side overhead and requires a supported cache backend (XFS, ext3, ext4).
- **NFS mount options `rsize` and `wsize` defaults clarified**: The maximum transfer size for NFS read/write operations is now explicitly defined as 1,048,576 bytes (1 MiB) for both client and server in RHEL 10; this matters for performance tuning, as larger sizes can improve throughput for large file transfers.
- **NFS `port` option behavior clarified for NFSv4**: For NFSv4 mounts, if the `port` option is not specified, the client now uses the standard TCP port 2049 instead of querying `rpcbind`; this matters for simplifying firewall configurations and reducing dependency on `rpcbind` in NFSv4 environments.
