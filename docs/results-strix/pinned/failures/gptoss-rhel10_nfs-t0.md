- **NFS with TLS support (RHEL 10.0)** – RPC traffic for NFS is now encrypted using Transport Layer Security.  The feature is fully supported (via kernel TLS technology preview) and allows administrators to secure NFS mounts without changing client or server configuration beyond enabling TLS.  This improves confidentiality and integrity of NFS traffic, especially over untrusted networks.  

- **IPv6 address parsing bug fix for `nfs://` URLs (RHEL 10.0)** – Square‑bracketed IPv6 addresses are now correctly interpreted in `nfs://` and `sshfs://` URLs used by tools such as ReaR.  The previous bug caused ReaR to abort with “Invalid scheme” errors when an IPv6 address was enclosed in brackets.  The fix restores proper URL handling, enabling reliable use of IPv6 NFS endpoints in backup and restore workflows.  

- **Client‑side caching of NFS content via FS‑Cache (RHEL 10.0)** – RHEL 10 introduces the `cachefilesd` daemon and `cachefiles` kernel module to provide FS‑Cache support for NFS mounts.  When enabled, the client can cache read data locally on a block‑based filesystem (XFS, ext3, ext4) with extended attributes, reducing network traffic and server load while improving read performance for frequently accessed files.  Administrators can configure the cache backend and size through `/etc/cachefilesd.conf`.
