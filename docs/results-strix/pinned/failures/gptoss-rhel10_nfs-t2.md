- **NFS with TLS support (new feature)** – RHEL 10 now allows NFS RPC traffic to be encrypted with Transport Layer Security.  The kernel TLS (kTLS) technology preview is required, but the feature is fully supported in the NFS server and client configuration.  This change improves data confidentiality and integrity for NFS traffic, especially over untrusted networks, without requiring separate VPN or IPsec tunnels.

- **IPv6 address parsing bug fix for `nfs://` URLs** – Previously, ReaR (and other tools that parse `nfs://` URLs) incorrectly treated square brackets around an IPv6 address as shell metacharacters, causing the backup or output URL to be rejected.  The fix now correctly ignores the brackets, allowing `nfs://[2001:db8:ca2:6::101]/path` to be used directly.  This eliminates a common configuration error and enables reliable use of IPv6 NFS endpoints in backup scripts and other automation.

- **Client‑side caching of NFS content via FS‑Cache (new feature)** – RHEL 10 introduces full FS‑Cache support for NFS mounts.  The `cachefiles` kernel module and `cachefilesd` daemon provide a persistent local cache backed by a block‑based filesystem (XFS, ext3, or ext4).  When an NFS share is mounted with the appropriate option, read requests are served from the local cache whenever possible, reducing network traffic, lowering server load, and improving client‑side read performance.  The feature is transparent to users and can be enabled or disabled per‑mount, giving administrators fine‑grained control over performance trade‑offs.
