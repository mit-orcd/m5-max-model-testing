- **NFS with TLS support is fully supported**: NFS now supports Transport Layer Security (TLS) for encrypting RPC traffic between clients and servers, enhancing security for NFS communications. This matters because it protects data in transit from eavesdropping and tampering, meeting modern security requirements for sensitive workloads.  
  *Note: This relies on kernel TLS (kTLS), which is a Technology Preview in RHEL 10.*

- **IPv6 address handling in NFS URLs fixed**: Previously, ReaR (Relax-and-Recover) failed to parse IPv6 addresses in `nfs://` URLs when enclosed in square brackets due to incorrect interpretation of brackets as shell metacharacters. This fix allows proper use of IPv6 addresses in NFS URLs (e.g., `nfs://[2001:db8:ca2:6::101]/path`) without workarounds, enabling reliable backup and recovery operations in IPv6-only or dual-stack environments.

- **NFS client-side caching via FS-Cache is documented and enabled**: The guide details how FS-Cache, backed by `cachefilesd`, enables transparent client-side caching of NFS content to improve performance, reduce server load, and allow efficient local data retrieval. It works with XFS, ext3, and ext4 as cache back ends and can cache partial files while hiding cache I/O errors from the client. This matters because it significantly reduces network traffic and server load for repetitive read workloads, improving scalability and responsiveness—especially beneficial in virtualized or high-latency network environments.  
  *Note: While enabling caching may slightly slow the client due to cache lookup overhead, the net gain in reduced network/server load typically outweighs this cost.*
