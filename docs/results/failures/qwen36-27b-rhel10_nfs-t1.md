*   **NFS with TLS support**: RHEL 10 fully supports NFS over Transport Layer Security (TLS) for RPC traffic, enabling encrypted communication between clients and servers. This matters because it significantly enhances security by protecting data in transit, though it relies on the Technology Preview feature kTLS (kernel TLS).
*   **Increased default max rsize/wsize**: The maximum value for read (`rsize`) and write (`wsize`) transfer sizes for NFS clients and servers is now 1,048,576 bytes. This matters because larger transfer sizes can improve throughput and performance for high-bandwidth networks and large file operations.
*   **FS-Cache integration for NFS**: The documentation details the use of FS-Cache (via the `cachefiles` back end) to enable client-side caching of NFS content. This matters because it can massively reduce network bandwidth usage and server load by satisfying read requests locally, although it may introduce latency for initial file access or cache misses.
*   **ReaR NFS/SSHFS URL parsing fix**: A bug in the ReaR (Relaxed and Ready to Roll) backup tool fixed the handling of IPv6 addresses in `nfs://` (and `sshfs://) URLs. Previously, square brackets required for IPv6 literals were misinterpreted as shell metacharacters causing aborts; the fix allows correct parsing of IPv6 addresses in NFS backup URLs.
