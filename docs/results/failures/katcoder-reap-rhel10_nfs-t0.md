*   **NFS now supports TLS for RPC traffic**: RHEL 10 fully supports NFS with Transport Layer Security (TLS), enabling encrypted communication between clients and servers. This matters for security, though it relies on the Technology Preview kTLS feature.
*   **NFS mount option `vers` is retained for compatibility**: The `vers` option is now identical to `nfsvers` and included for compatibility reasons.
*   **NFS `rsize` and `wsize` maximum increased to 1,048,576 bytes**: The maximum transfer size for single NFS read/write operations is now 1,048,576 bytes (1 MB) by default when both client and server support it. This matters for optimizing throughput on high-performance networks.
*   **NFS caching via FS-Cache is supported**: NFS can leverage FS-Cache to improve client performance and reduce server load by caching data locally. This matters for workloads with repeated read access, though it may slow clients down if not tuned correctly and requires specific back-end file systems (XFS, ext3, ext4).
*   **ReaR fixed to correctly parse IPv6 addresses in NFS URLs**: ReaR no longer misinterprets square brackets in `nfs://` URLs as shell metacharacters. This matters because it allows automated backups/outputs to NFS servers using IPv6 addresses without requiring manual workarounds.
