*   **NFS with TLS support is fully enabled**: NFS now supports Transport Layer Security (TLS) for RPC traffic, ensuring encrypted communication between clients and servers. This matters for enhancing security by protecting NFS traffic from eavesdropping and tampering, though it relies on the kernel TLS (kTLS) feature.
*   **NFS URL parsing fixed for IPv6 addresses**: The ReaR tool no longer misinterprets square brackets in `nfs://` URLs as shell metacharacters. This matters because it allows users to correctly use IPv6 addresses in NFS backup and output URLs without requiring manual workarounds.
*   **Default NFS `rsize` and `wsize` maximum increased to 1,048,576 bytes**: The maximum number of bytes transferred in a single NFS read or write operation is now 1 MB. This matters because it increases the default transfer size, potentially improving NFS read and write performance by reducing overhead.
*   **NFS client-side caching via FS-Cache supported**: The system supports leveraging FS-Cache to cache NFS content locally. This matters because it can improve performance and reduce server load by satisfying read requests locally without consuming network bandwidth, although it may slightly slow down the client.
