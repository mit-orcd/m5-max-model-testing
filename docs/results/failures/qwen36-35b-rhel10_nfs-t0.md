*   **NFS with TLS support is fully supported**: This feature enhances security by enabling TLS for RPC traffic, ensuring encrypted communication between clients and servers. It matters for organizations requiring encrypted NFS traffic, though it relies on kernel TLS (kTLS) which is currently a Technology Preview.
*   **ReaR correctly interprets square brackets in NFS URLs with IPv6 addresses**: Previously, ReaR aborted when parsing `nfs://` URLs containing IPv6 addresses enclosed in square brackets (e.g., `nfs://[::1]`), treating brackets as shell metacharacters. The fix allows users to specify IPv6 addresses in backup/output URLs without manual quoting workarounds, ensuring reliable NFS-based disaster recovery operations.
*   **Default `rsize` and `wsize` maximum increased to 1,048,576 bytes**: Red Hat Enterprise Linux 10 sets the maximum read/write size for NFS to 1 MB (previously unspecified or lower). This matters because it allows the NFS client and server to negotiate larger transfer sizes by default, potentially improving throughput for large file operations.
*   **FS-Cache integration for NFS**: Enabling FS-Cache allows NFS clients to cache content locally, which reduces server load and network bandwidth usage by satisfying read requests from the local cache. This matters for improving performance in scenarios with high read latency or limited network bandwidth, though it requires a compatible back-end file system (XFS, ext3, or ext4) and may introduce local caching overhead.
