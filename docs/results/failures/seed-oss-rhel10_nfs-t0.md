- **NFS with TLS support added**: RHEL 10 now fully supports NFS with Transport Layer Security (TLS), enabling encrypted RPC traffic between clients and servers. This enhances security by protecting data in transit, though it relies on kernel TLS (kTLS) which is a Technology Preview.  
- **NFS client IPv6 URL support fixed**: Previously, using an IPv6 address in `nfs://` URLs required workarounds (e.g., quoting/backslashes) due to incorrect parsing of square brackets. The fix allows proper use of IPv6 addresses like `nfs://[2001:db8::1]/path` in tools like ReaR, simplifying URL configuration.  
- **NFS client-side caching via FS-Cache enabled**: NFS can now leverage FS-Cache (using the `cachefilesd` service) to improve performance by caching data locally. This reduces network/server load and speeds up repeated access to NFS content, with support for XFS/ext3/ext4 as cache backends.  
- **NFS mount option defaults updated**: RHEL 10 NFS clients/servers use a maximum `rsize/wsize` of 1,048,576 bytes (1MB) by default (up from earlier releases), allowing larger data transfers per request to boost performance.  
- **`vers` option compatibility for NFS**: The `vers` mount option (identical to `nfsvers`) is included for compatibility with older systems, simplifying migration or interaction with legacy NFS setups.
