- **NFS with TLS support (Technology Preview)** – RHEL 10 now fully supports NFS over TLS, using kernel TLS (kTLS) to encrypt RPC traffic. This adds a security layer for NFS server/client communication, enabling secure deployments while noting that kTLS is still a preview feature and may impact performance due to encryption overhead.  

- **IPv6 address parsing fix for nfs:// URLs** – A bug in ReaR caused nfs:// and sshfs:// URLs containing IPv6 addresses in brackets (e.g., `nfs://[2001:db8::1]/`) to abort with “Invalid scheme”. The fix ensures brackets are correctly interpreted, allowing IPv6 hosts to be used as NFS servers in BACKUP_URL/OUTPUT_URL. This restores reliability for IPv6‑based NFS client configurations.  

- **Client‑side NFS caching via FS‑Cache (cachefilesd)** – RHEL 10 introduces native NFS client caching that leverages the `cachefiles` back‑end and the `cachefilesd` daemon. By mounting an NFS share with the caching option, read operations are served locally, dramatically reducing network traffic and server load while improving response times. The feature is configurable through `/etc/cachefilesd.conf` and requires an ext3/4 or XFS cache device with extended attributes, providing a tunable performance boost for NFS workloads.
