*   **NFS with TLS support**: RHEL 10 fully supports NFS with Transport Layer Security (TLS) to encrypt RPC traffic between clients and servers. This matters for security, though it relies on kernel TLS (kTLS), which is currently a Technology Preview.
*   **ReaR NFS URL parsing fix**: The ReaR backup tool now correctly interprets square brackets in `nfs://` URLs containing IPv6 addresses (e.g., `nfs://[2001:db8::1]/share`). Previously, these brackets were misinterpreted as shell metacharacters, causing premature aborts; this fix allows seamless use of IPv6 NFS targets in backup configurations.
*   **Increased default rsize/wsize limits**: The maximum supported value for `rsize` and `wsize` (read/write buffer sizes) is now 1,048,576 bytes for both client and server. This matters for performance, as larger transfer sizes can improve throughput for large file operations compared to previous defaults.
*   **FS-Cache for NFS performance**: Documentation highlights the use of FS-Cache (via `cachefiles`) to cache NFS content locally. This matters for performance by reducing network bandwidth usage and server load, allowing read requests to be satisfied from local storage, though it may introduce slight latency overhead on the client.
