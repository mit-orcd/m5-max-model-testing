- NFS with TLS support is fully supported in RHEL 10, enabling TLS for RPC traffic to encrypt client-server communication; it depends on kernel TLS (kTLS), which is a Technology Preview. This matters because it adds a new security option for NFS deployments, though it is not yet generally available.
- The maximum `rsize` and `wsize` for NFS mounts is now 1,048,576 bytes on both client and server in RHEL 10, up from previous limits. This matters because larger transfer sizes can improve NFS performance.
- ReaR now correctly parses `nfs://` URLs containing IPv6 addresses in square brackets (e.g., `nfs://[2001:db8:ca2:6::101]/root/REAR`) for `BACKUP_URL` and `OUTPUT_URL`, fixing premature aborts. This matters for backup/restore workflows using NFS with IPv6.
- `sec=krb5p` is documented as the most secure NFS security option, providing Kerberos V5 authentication, integrity checking, and encryption, but with the most performance overhead. This matters for administrators choosing the right security/performance trade-off for NFS mounts.
